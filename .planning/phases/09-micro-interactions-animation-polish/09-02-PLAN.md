   Replace the DialogContent component. The key challenge: Radix Dialog's data-[state] CSS animations and framer-motion can conflict. Remove the `data-[state=open]:animate-in data-[state=closed]:animate-out` CSS classes since framer-motion replaces them. Keep all positioning and styling classes.

   New DialogContent:
   ```typescript
   export const DialogContent = React.forwardRef<
     React.ElementRef<typeof DialogPrimitive.Content>,
     React.ComponentPropsWithoutRef<typeof DialogPrimitive.Content>
   >(({ className, children, ...props }, ref) => (
     <DialogPortal>
       <DialogOverlay />
       <LazyMotion features={loadFeatures} strict>
         <DialogPrimitive.Content
           ref={ref}
           asChild
           {...props}
         >
           <m.div
             initial={{ opacity: 0, scale: 0.95 }}
             animate={{ opacity: 1, scale: 1 }}
             exit={{ opacity: 0, scale: 0.95 }}
             transition={TRANSITIONS.smooth}
             className={cn(
               'fixed left-1/2 top-1/2 z-50 grid w-full max-w-lg -translate-x-1/2 -translate-y-1/2 gap-4 border bg-background p-6 shadow-lg sm:rounded-lg ring-1 ring-border/50',
               className,
             )}
           >
             {children}
             <DialogPrimitive.Close
               className="absolute right-4 top-4 rounded-sm opacity-70 ring-offset-background transition-opacity hover:opacity-100 focus:outline-none focus:ring-2 focus:ring-ring focus:ring-offset-2"
               aria-label="Close"
             >
               <X className="h-4 w-4" />
             </DialogPrimitive.Close>
           </m.div>
         </DialogPrimitive.Content>
       </LazyMotion>
     </DialogPortal>
   ));
   DialogContent.displayName = DialogPrimitive.Content.displayName;
   ```

   IMPORTANT NOTES:
   - `asChild` on DialogPrimitive.Content makes it delegate rendering to the child `m.div`, so Radix handles focus trap/escape while framer-motion handles animation.
   - The `data-[state=open/closed]:animate-in/animate-out` classes are REMOVED since framer-motion replaces that functionality.
   - The overlay (DialogOverlay) keeps its existing CSS animation — only the content panel gets framer-motion.
   - `exit` prop works because Radix unmounts content when closed. If exit animation doesn't fire, it means the component unmounts before framer-motion can animate. In that case, the entrance animation alone (scale-in from 0.95) is still a significant improvement over the current instant appearance. The MotionConfig reducedMotion="user" from main.tsx handles accessibility globally.

     <m.div
       className="divide-y"
       variants={STAGGER.container}
       initial="hidden"
       animate="show"
       key={tab}  // Re-trigger animation when switching tabs
     >
       {isPending ? (
         // Keep existing skeleton loading block unchanged

               <Skeleton className="h-3 w-1/2" />

           {tab === 'unread'

             : 'No notifications yet'}
         </p>

         filteredNotifications.map((n) => (

           >
             <div className="flex items-start gap-3">
               {!n.isRead && (
                 <span className="mt-1.5 h-2 w-2 rounded-full bg-primary shrink-0" />

                 <p className={cn('text-sm', !n.isRead && 'font-medium')}>
                   {n.title}
                 </p>
                 <p className="mt-0.5 text-xs text-muted-foreground line-clamp-2">
                   {n.body}
                 </p>
                 <p className="mt-1 text-[10px] text-muted-foreground">
                   {formatRelative(n.createdAt)}
                 </p>
               </div>
             </div>
           </m.button>
         ))
       )}
     </m.div>
   </LazyMotion>
