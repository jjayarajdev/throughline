# Plan 05-01: Design System Foundation

## Objective

Establish the visual identity and token infrastructure for the fastalent rebrand: Deep Teal OKLCH palette with light/dark semantic tokens, Inter variable font with proper preload and fallback metrics, dark mode via next-themes with no flash, and complete rebrand of all user-visible "GigCruite" references. This is the foundation that every subsequent phase (6-10) builds on -- no component can be restyled until these tokens, typography, and dark mode plumbing exist.

Purpose: Lock the visual DNA (colors, type, dark mode) so all downstream work inherits it automatically via CSS custom properties. Ship the rebrand atomically -- no page should ever show "GigCruite" after this plan completes.

Output: Updated `index.css` with Deep Teal tokens + Inter font + @theme mappings, `ThemeProvider` in place with no-FOUC script, theme toggle in Topbar, all branding replaced with "fastalent".

**index.css** has shadcn/ui's default grayscale OKLCH tokens (--primary is gray `oklch(0.205 0 0)`) with a working `@theme inline` block. The `@custom-variant dark` directive is already present.

**App.tsx** manually toggles `.dark` class on `<html>` via a `useEffect` reading from Zustand `ui-store`. This is the FOUC source -- on refresh, React must hydrate before the class is applied.

### Task 2: Inter Font Loading with Fallback Metrics

**Files:**
- `apps/web/index.html` (modify -- add preconnect + font link)
- `apps/web/src/index.css` (modify -- add @font-face fallback + update body font-family)

**What:**

1. Add Inter font loading to `index.html` `<head>` (before the closing `</head>`):
   ```html
   <!-- Inter variable font (Latin subset, font-display: swap in URL) -->
   <link rel="preconnect" href="https://fonts.googleapis.com" />
   <link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
   <link href="https://fonts.googleapis.com/css2?family=Inter:ital,opsz,wght@0,14..32,100..900;1,14..32,100..900&display=swap" rel="stylesheet" />
   ```

   Using Google Fonts CDN (not self-hosted) per STACK.md recommendation. The `display=swap` parameter is in the URL, ensuring `font-display: swap` is applied. `preconnect` to both domains ensures early DNS + TLS handshake.

2. Add Inter fallback font-face with size-adjust to `index.css` (above the `@layer base` block):
   ```css
   /* Inter fallback -- matches system font metrics to Inter to minimize CLS */
   @font-face {
     font-family: 'Inter Fallback';
     src: local('Arial'), local('Helvetica Neue'), local('Helvetica');
     size-adjust: 107%;
     ascent-override: 90%;
     descent-override: 22%;
     line-gap-override: 0%;
   }
   ```

3. Update the `body` font-family in `@layer base` to use Inter + fallback:
   ```css
   body {
     font-family:
       'Inter',
       'Inter Fallback',
       system-ui,
       -apple-system,
       'Segoe UI',
       sans-serif;
     -webkit-font-smoothing: antialiased;
     font-feature-settings: 'cv11', 'ss01';
   }
   ```

   `cv11` = single-storey "a" for better UI readability. `ss01` = open digits for financial data.

4. Add Inter to Tailwind's font-sans via `@theme inline` (append):
   ```css
   --font-sans: 'Inter', 'Inter Fallback', system-ui, -apple-system, 'Segoe UI', sans-serif;
   ```

5. Add a utility class for tabular numerals (financial data in tables/dashboards):
   ```css
   .tabular-nums {
     font-variant-numeric: tabular-nums;
   }
   ```

**IMPORTANT -- what NOT to do:**
- Do NOT self-host the font (research suggested it, but Google Fonts CDN with preconnect is simpler and cached globally). Self-hosting adds build complexity with Vite.
- Do NOT use `font-display: optional` -- it can cause invisible text on slow connections, which is worse for UX than a brief swap.
- Do NOT load italic axis unless needed -- saves bandwidth. The URL above includes italic (`ital`), which adds ~50KB. If bundle becomes an issue, remove the italic axis.

**Acceptance:**
- Dev server serves pages with Inter font visible (inspect body in DevTools -- font-family shows "Inter")
- Throttle to "Fast 3G" in DevTools Network panel, hard refresh -- text appears immediately in fallback, then swaps to Inter with minimal shift
- Financial numbers on any existing page remain stable width during swap (the `size-adjust: 107%` fallback prevents column jump)
- `font-feature-settings: 'cv11', 'ss01'` visible in computed styles

### Task 3: Dark Mode via next-themes (Replace Zustand Theme Logic)

**Files:**
- `apps/web/src/main.tsx` (modify -- wrap with ThemeProvider)
- `apps/web/src/App.tsx` (modify -- remove manual theme effect)

- `apps/web/src/components/layouts/Topbar.tsx` (modify -- add ThemeToggle)

**What:**

1. **main.tsx** -- Add `ThemeProvider` from `next-themes`. Place it INSIDE `StrictMode` but OUTSIDE `QueryClientProvider` (theme is independent of data):
   ```tsx
   import { ThemeProvider } from 'next-themes';

   createRoot(rootEl).render(
     <StrictMode>
       <ThemeProvider attribute="class" defaultTheme="system" enableSystem disableTransitionOnChange>
         <QueryClientProvider client={queryClient}>
           <RouterProvider router={router} />
           <Toaster position="top-right" richColors closeButton />
           <ReactQueryDevtools initialIsOpen={false} />
         </QueryClientProvider>
       </ThemeProvider>
     </StrictMode>,
   );
   ```

   `attribute="class"` -- toggles `.dark` on `<html>` (matches Tailwind v4's `@custom-variant dark`).
   `defaultTheme="system"` -- respects OS preference on first visit.
   `enableSystem` -- watches `prefers-color-scheme` media query for live updates.
   `disableTransitionOnChange` -- prevents a flash of CSS transitions when toggling (elements briefly animate between light/dark colors otherwise).

   **CRITICAL**: next-themes injects a blocking `<script>` in `<head>` that reads localStorage and sets the class BEFORE React hydrates. This eliminates FOUC -- the correct theme is applied before any paint.

2. **App.tsx** -- Remove the `useEffect` that manually toggles `.dark`. Remove the `useUiStore` import for theme. The component simplifies to:
   ```tsx

     return (
       <div className="min-h-full bg-background text-foreground page-fade-in">
         <Outlet />
       </div>
     );
   }
   ```

3. **ui-store.ts** -- Remove `theme`, `setTheme`, `toggleTheme` from the store. Update the `Theme` type export to come from next-themes if other components need it. Change the localStorage key from `gigcruite.ui` to `fastalent.ui` (part of rebrand). Update the `UiState` interface and `persist` config:
   ```ts
   interface UiState {
     sidebarOpen: boolean;
     activeModal: ModalId | null;
     toggleSidebar: () => void;
     setSidebarOpen: (open: boolean) => void;
     openModal: (id: ModalId) => void;
     closeModal: () => void;
   }
   ```
   Remove the `partialize` for theme (no longer stored here). Update `name: 'fastalent.ui'`. Keep `version: 1` (the shape changed, but Zustand persist handles missing keys gracefully).

   Remove `export type Theme = 'light' | 'dark';` -- no longer needed.

4. **Create `apps/web/src/components/ThemeToggle.tsx`** -- A dropdown button with three options: Light, Dark, System.

### Task 5: Contrast Validation and Utility Classes

**Files:**

**What:**

1. **Validate WCAG AA contrast** for all primary teal + background combinations:

   | Pair | Light Mode | Dark Mode | Requirement |
   |------|-----------|-----------|-------------|
   | teal-600 on white | Must pass 4.5:1 | N/A | Body text |
   | teal-400 on dark bg | N/A | Must pass 4.5:1 | Body text |

## Risks

- **OKLCH contrast values may need tuning**: The lightness values in this plan are theoretical. During Task 5, actual contrast ratios must be validated and adjusted. If teal-600 doesn't pass 4.5:1 on white, decrease lightness to 0.44-0.45. Mitigation: Task 5 includes explicit contrast check and adjustment step.

- **Inter font CLS on very slow connections**: Even with `size-adjust` fallback, edge cases (slow 2G) may show brief reflow. Mitigation: `font-display: swap` ensures text is always visible; the fallback metrics minimize the shift to sub-0.1 CLS. Monitor after deploy.

- **59-file rebrand may have edge cases**: Some "GigCruite" references may be in string templates, error messages, or concatenated strings that a simple find-replace misses. Mitigation: Task 4 includes a final `grep -r "GigCruite"` verification to catch stragglers.

- **next-themes + Zustand migration timing**: During Task 3, there's a brief window where the old Zustand theme logic is removed and the new next-themes is wired. If done out of order, theme breaks. Mitigation: Task 3 is atomic -- all changes happen together before committing.

- **@gigcruite/types import alias**: Not renaming this alias means internal imports still say "gigcruite". This is acceptable per NFR-03 (no backend changes). A workspace-wide rename can happen in a future milestone if the backend is also rebranded.
